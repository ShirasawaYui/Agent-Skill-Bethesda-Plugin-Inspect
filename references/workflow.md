# 查询流程细则

> 版本：v1.0.0 · 最后更新：2026-10-01

主流程只有三步：**定位 → 解析 → 归因**。任何一步跳过，结论都可能取到过时或错误的定义。

```
定位：哪个插件改了它？
  ↓
解析：改成了什么？（字段级）
  ↓
归因：哪一份最终生效？（覆盖链）
  ↓
（按需）脚本分支：VMAD → pex 反编译
（按需）归档分支：bsa/ba2 提取
```

---

## 第一步：定位

**目标**：在数百个插件中找出哪几个动了目标记录。

判据优先级：

| 手段 | 适用 | 可靠性 |
|---|---|---|
| 记录级搜索（`esp_inspect.py find`） | 已知 EditorID 或显示名 | 高——匹配的是记录字段，不是原始字节 |
| 纯字节串搜索 | 连 EditorID 都不知道，只记得某段文本 | 低——会把"出现在任意位置的字符串"也算命中，必须二次核实 |
| 已知 FormID 反查 | 已有目标 FormID | 高——但需先还原覆盖链才有意义 |

**结论要落到"哪个插件、哪条记录（signature + editor_id + form_id）"，而不是"某个词出现在某个文件里"。**

中文关键词要防子串误报：一个词可能同时是无关记录名的一部分。命中后必须看记录的 signature 和上下文，确认语义相符。

## 第二步：解析

**目标**：把记录解成可读字段。

使用 schema 类型化解码（`esp_inspect.py dump`），得到与 SSEEdit 界面一致的字段名，不要自己推算字节偏移。

解读时的注意事项：

- **位标志优先看**。例如 `Auto-calc stats` 打开时，等级与属性由引擎推算，记录中的显式数值可能不参与运算。
- **枚举与引用要还原含义**。`Aggression`、`Confidence` 这类枚举值要读解出的名字；指向其他记录的引用要顺着 `TypedFormId` 继续查，才能知道指向什么。
- **空值不等于是零**。某些字段未设置时显示为空或 0，代表"沿用默认/继承"，不等于被显式设为零。

## 第三步：归因（最容易出错的一步）

**目标**：确定哪一份定义最终生效。

同一条记录常被多个插件依次覆盖（补丁、汉化、难度调整、兼容补丁）。**先找到的那一份往往不是生效的那一份。**

做法：读取配置档的 `plugins.txt`，按 `*` 标记取出启用插件的 load order，逐条 `PluginCache.add()` 建索引，再还原覆盖链（`esp_inspect.py chain`）。

输出应形如：

```
[212] A.esp    EditorID=old_name    44 字段
[402] B.esp    EditorID=new_name    50 字段
[420] C.esp    EditorID=new_name    86 字段   ← 最终生效
```

必须核对的三件事：

1. **最终生效的是哪一份**——load order 最靠后的那一条。
2. **EditorID 是否被改过**——若被改名，用原名检索会一无所获，容易误判"某插件没动它"。
3. **字段差异**——生效版可能比首版多出若干关键子记录（脚本挂载、法术、Perk 数量等），只看首版会得出错误结论。

**给出任何结论前都要先完成归因。**「找到记录」不等于「找到生效记录」。

## 脚本分支（按需）

若生效版本的记录**含 VMAD**，说明挂了脚本，行为逻辑需读脚本内容：

1. 从 VMAD 取出脚本名；
2. 在插件的 `Scripts/` 目录或相关 bsa 中定位同名 `.pex`；
3. 用 Champollion 反编译为 `.psc` 后阅读。若技能目录下已有 `tools/champollion/` 则直接调用；
   否则从官方 releases 获取（见 `SKILL.md` 的「可选工具」）。输出落在**当前工作目录**。

注意：`VMAD` 只说明"挂了这个脚本"，脚本内部对数值的修改（比如按血量切换形态、临时改变抗性）不会体现在记录的字段里。**记录显示的抗性 ≠ 运行时实际抗性**，涉及脚本的记录只能给"待实测"的结论。

## 归档分支（按需）

插件引用的资源（模型、贴图、音频、脚本）可能打包在 `.bsa` / `.ba2` 中。

优先用 bethkit 内置的归档读取，无需外部工具：

```python
import bethkit
with bethkit.Archive.open(path_bsa) as ar:
    for e in ar.entries():
        print(e.path)
    ar.extract_to_file("meshes/foo.nif", out_path)
```

需要图形界面批量浏览时用 BSA Browser（获取方式见 `SKILL.md` 的「可选工具」）。

已解包的资源不必提取。资源**内容**本身（模型形态、贴图效果）需要专门的查看器，不属于本技能范围。

## 验证

结论给出前做一次交叉校验：

- 用另一条独立路径复核（换了检索方式或换了记录类型），结果一致才输出。
- 与游戏内可观察的事实对照（如界面上显示的数值），不一致时优先怀疑解析口径而不是游戏。
- 无法交叉校验时，明确标注为待验证，不要省略这个标注。

## 交付形态

| 场景 | 输出 |
|---|---|
| 单点查询 | 记录清单：插件、signature、editor_id、关键字段值 |
| 覆盖比较 | 覆盖链表 + 生效版本 + 与首版的字段差异 |
| 脚本行为 | 反编译后的关键逻辑，标注哪些是记录可证、哪些依赖运行 |
